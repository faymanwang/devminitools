图片压缩：尺寸、格式与透明背景

打开 图片压缩工具。工具使用浏览器 Canvas 重新编码静态图片，不保证把任意文件压到某个固定体积。

用同一张原图比较

下载本教程的透明 PNG 原图。它是 640 × 480 的合成测试图，包含渐变矩形和文字，四角透明。没有使用用户照片或需要转载授权的图片。

实测环境：Windows，Chrome 155.0.8059.82，Canvas 编码，质量 80%。原图 PNG 为 192201 B，640 × 480。

image/png, 640 × 480: 192201 B; RGBA(0,0) = 0, 0, 0, 0.

image/jpeg, 640 × 480: 6523 B; RGBA(0,0) = 255, 255, 255, 255.

image/webp, 640 × 480: 4126 B; RGBA(0,0) = 0, 0, 0, 0.

image/webp, 320 × 240: 2062 B; RGBA(0,0) = 0, 0, 0, 0.

选择原图，先清空最大宽高，再依次导出 PNG、JPEG 80% 和 WebP 80%。最后保持 WebP 80%，把最大宽度设为 320，下载并查看实际尺寸。每次都应比较输出文件，而不只看网页预览。

质量、尺寸和格式分别改变什么

PNG 导出不使用质量参数，主要通过缩小尺寸改变体积。JPEG 不支持透明，因此工具会填充白色背景。WebP 可以保留透明，但是否支持导出取决于浏览器；工具会核对实际输出类型，避免把回退的 PNG 误命名为 WebP。

宽高限制保持原始比例，不放大图片。640 × 480 的原图限制到宽 320 后，应得到 320 × 240。质量滑块主要影响 JPEG 和 WebP 的有损编码，具体字节数依赖浏览器和图像内容。

失败和结果变大的情况

没有选择图片时应提示先选择文件。负数、零和非整数尺寸会被拒绝；失败后旧下载结果失效。损坏文件或超大图片可能受解码和设备内存限制。

已经优化过的图片重新编码可能变大，页面会显示「增大」比例。PNG、WebP 的透明输出和 JPEG 的白底可在下载后检查。工具只处理静态单帧，不保证保留动画、EXIF、色彩配置或其他元数据；上传平台还可能再次编码。
